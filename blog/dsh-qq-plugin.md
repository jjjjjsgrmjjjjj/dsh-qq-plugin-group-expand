# 把 DeepSeek Harness 装进 QQ：dsh-qq-plugin-group-expand 开发手记

## 缘起：想在手机上指挥电脑里的 agent

我用 DeepSeek Harness（DSH）在电脑上干活的时间越来越多。它能把一个想法拆成步骤、读写文件、跑命令、查资料，但有一个很现实的问题：**人不可能一直坐在电脑前**。

出门在外，地铁上、饭桌上、床上，想起来一件事，最顺手的设备是手机。于是就有了这个插件：把 QQ 变成 DSH 的遥控器。发一条消息，电脑上的 agent 开始干活；它做完、卡住、需要权限，都会回到 QQ 里。

项目名很直白：`dsh-qq-plugin-group-expand`。它不是另一个聊天机器人，而是 **DSH 的一条渠道**——和微信、Web 界面并列，只不过这条渠道的另一端是 QQ。

## 为什么是 QQ 官方机器人

做 QQ 机器人有两条路：

1. **个人号协议**（NapCat、SnowLuma 之类）：能看到群里所有消息，像真人一样参与聊天；
2. **腾讯官方机器人**：扫码绑定，走官方 WebSocket 和 HTTP API，不需要公网 IP，不需要反向代理。

我选官方机器人，原因只有两个字：**省事**。扫码一次，机器人当场创建，之后一直有效；不用维护协议客户端，不用担心掉线重登，也不碰自己的 QQ 账号。

代价也很明确：**官方机器人默认只能收到群里 @ 它的消息**。普通群聊对它来说是不存在的，除非申请到“群消息全量”权限。这不是代码能绕过去的限制，也是后面很多设计取舍的起点。

## 整体结构

插件挂在 DSH 的 Host 侧，入口是 `index.js` 的 `apply(ctx, config)`。它做了三件事：

- 解析状态文件、凭据、会话工作目录；
- 创建 `QqRuntime`，通过 `ctx.provide('qqChannel', runtime)` 暴露给设置页；
- 用 `ctx.effect` 注册 QQ bot 的 WebSocket 事件、路由和工具，插件卸载时统一清理。

核心模块各管一段：

| 模块 | 职责 |
|---|---|
| `runtime.js` | 连接 QQ、入站消息、会话提交、助手流聚合、发送 |
| `router.js` | 一个 QQ 对话对应哪个 DSH 会话，以及 `/new` `/list` `/switch` 等指令 |
| `state.js` | 原子写、串行化的状态文件；会话映射、待发队列、设置 |
| `prompt.js` | 把 QQ 消息拼成给 agent 的提示词，处理引用 |
| `media.js` | 图片、文件、语音落盘，交给 agent 本地路径 |
| `settings.js` | 设置项的唯一一份 schema |
| `group.js` | 群聊门禁、人格判定、连续对话、静默标记 |
| `stickers.js` | 群表情包收藏、去重、上限 |
| `client.js` | 设置页 UI |

一条消息的路径大致是：

```text
QQ 消息
  → WebSocket 事件
  → 去重 / 解析引用与附件
  → router 决定：指令直接回，还是交给某个 DSH 会话
  → sessionController.prompt()
  → 助手流聚合
  → 发回 QQ（被动回复，失败再走主动推送或队列）
```

## 几个关键设计

### 1. 一个 QQ 对话，多个 DSH 会话

QQ 里只有一个聊天窗口，但背后可以有好几条互不干扰的 DSH 会话。`/new` 创建、`/list` 列出、`/switch` 切换，列表分“会话夹”和“会话”两层，每屏 10 条，编号跨屏连续。手机键盘不好打字，所以编号、标题、行尾短 id 都能用来切换。

这里踩过一个坑：会话 id 在 DSH 里是 `session-<8hex>-<uuid>`，我最初按标题匹配，结果重名会话永远切不对。后来统一成“编号由路由印、按那条消息的清单解析”，引用一条旧清单再回编号也不会串屏。

### 2. 附件先落盘，再把本地路径交给 agent

QQ 的附件 URL 是**会过期的 CDN 链接**。如果只把 URL 塞进提示词，agent 过一会儿再去取，多半已经 404。所以在收到消息的当下就下载到会话工作区，提示词里给绝对路径。

语音更省事：QQ 服务端直接给 `voice_wav_url` 和 `asr_refer_text`，不用自己解码 SILK，转写文本随消息一起来。

引用里的图片也一样：QQ 把被引消息的附件放在 `msg_elements[<refMsgIdx>].attachments`，原来提示词只写一句“（引用了 image/png）”，agent 根本看不到图。现在会先把引用图片下载下来，再把本地路径交给它。

### 3. 权限与审批回流

DSH 在会话开始时锁定权限预设。默认预设是「仅可查看」：新窗口只能看，不能写文件、不能执行命令。要让某条会话动手，得在它第一个回合前切换预设。

权限提示可以发到 QQ：一条“允许 / 拒绝”的消息，回一个词或数字就完成审批。这样离开电脑时，任务不会卡在一个没人看的弹窗上。

### 4. 主动推送与待发队列

`notify_qq` 让这台机器上的**任意会话**都能往 QQ 发消息——这就是“干完了告诉我”的实现。QQ 对主动消息有频率和权限限制，所以发送失败不会丢：消息进队列，等用户下次说话时先补发。

### 5. 群聊：从“@ 才理”到“像群友一样判断”

群聊和私聊是两套礼貌规则。私聊每条都是对它说的；群里绝大多数不是。所以群聊默认只在这几种情况下开口：

- 被 @：立刻回答；
- 被 @ 后的 5 分钟窗口内：每条文字消息都交给 agent，由它判断要不要回；
- 没有窗口时：只有提到人格名、关键词或语境才接话；
- 判断为无关：agent 输出 `[[NO_REPLY]]`，插件把整条回复丢掉，一个字都不发。

窗口内不再按关键词筛，是因为“像群友”不等于“听到关键词就插嘴”。让模型看到最近 8 条群消息（发送者 + 正文，单条截断），它自己判断这条是不是在跟自己说，比规则更自然，而且不额外调用一次模型。

### 6. 表情包：只收藏，不生成

群里的表情包是群的语言。程序画的鱼再可爱，也不是这个群的梗。所以插件只做两件事：

- 群里像表情包的方形小图，静默下载、哈希去重，收进 `collected/`，最多 300 张；
- 用户自己导入的图放在根目录，和收藏一起随机发送。

没有图就退到 emoji。简单，但够用。

## 踩过的坑

- **重复消息**：QQ 可能重复推送同一个 `msg_id`，必须去重，否则同一条消息会触发两轮。
- **空内容消息**：只有 @、没有正文的事件会带着空内容到达。早期直接丢弃，日志里一片空白；现在会留一行“收到过，但无可投递内容”。
- **群被动回复的 `msg_id`**：群里回复必须带最近一次 @ 的 `msg_id`，且只有 5 分钟有效期。用后续普通消息的 id 会被当成主动消息，而未认证的官方机器人没有群主动消息权限，接口直接拒绝。现在每个群记住最近一次 @，窗口内所有回复复用它。
- **`sendTyping` 只支持单聊**：群聊里调用会报错。它不该影响回复，所以错误只记录、不冒泡。
- **群消息全量**：官方平台默认只推 `GROUP_AT_MESSAGE_CREATE`，普通群聊消息根本不会到插件。要真正做到“仿真群友”，需要平台侧的群消息权限；这不是插件能单方面解决的。

## 测试

这个项目最花时间的不是功能，是让行为**可回归**。仓库里有三套离线自检：

- `scripts/verify.mjs`：纯函数与设置 schema，800+ 项；
- `scripts/verify-client.mjs`：用 stub React 和 stub fetch 驱动设置页，113 项；
- `scripts/verify-send-path.mjs`：用假 SDK 真跑运行时的发送路径，包括被动→主动降级、限流、群聊目标、渠道说明只发一次等，81 项。

它们不依赖 DSH 宿主，能在装进 profile 之前挡住“插件加载失败”“设置不生效”“群里发不出去”这类问题。

## 现在它是什么样

- 扫码绑定，一个 QQ 对话对应多个 DSH 会话；
- 文字、图片、文件、语音双向；
- 权限审批、二选一/多选提问能在手机上回答；
- 任意会话都能主动推送；
- 群聊只在被点名时说话，被 @ 后有 5 分钟连续对话窗口；
- 引用里的文字和图片都能作为上下文；
- 每个新对话只发一次渠道说明，省 token；
- 设置页有连接、权限、行为、群聊、指令、诊断。

它不是“让 AI 住进 QQ”，而是**把 QQ 变成一扇门**：门后面还是那台电脑、那些文件、那个会干活的 agent。手机只是换了一个更顺手的入口。

如果你也在用 DSH，又恰好常驻 QQ，欢迎试试。代码和文档都在仓库里，问题、想法、踩坑记录都欢迎。
